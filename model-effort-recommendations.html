dev-skills plugin — recommended model/effort pairs

Guidance for which session model/effort to run each skill under. The plugin deliberately pins neither in frontmatter, so everything inherits the session model — including subagents spawned by feature-plan, feature-implement, and the two eval skills.

SkillModelEffortRationale
feature-stormOpushighStep 3a must generate ideas the user didn't bring — breadth and judgement matter, but a human reviews everything before it becomes binding.
feature-designFablehighThe pivotal artefact: a guessed design silently costs a plan and an implementation. Highest-leverage thinking in the chain.
feature-planOpusmediumStructured decomposition of an already-closed design; needs solid codebase grounding but little open-ended reasoning.
feature-implementOpusmediumThe plan did the thinking; execution needs reliable coding, not deep design. Sonnet/high is a sound budget alternative when plans are tight.
feature-mockup (internal)OpusmediumFrontend taste and faithful rendering of the host project's design language; Sonnet/high acceptable.
feature-resolve (internal)HaikulowPure convention logic — pathing, versioning, tracker seeding. Anything stronger is wasted.
feature-dispatch (internal)SonnetlowThe hard part is staying silent correctly; Haiku misfires would be a recurring annoyance, but it's still just classification.
feature-listHaikumediumMulti-source parsing (trackers, stage files, git log), zero creativity, zero risk — it writes nothing.
bug-submitSonnetmediumTriage grounding needs competent code reading; no code changes are made.
bug-fixOpushighDebugging is the hardest routine task here; the root-cause gate is only as good as the model's evidence-gathering. Fable/high for gnarly ones.
bug-tracker-render (internal)HaikulowDeterministic template regeneration from filesystem state.
diagram-updateSonnetmediumNeeds accurate reading of all skills, but presentation is fully owned by the template.
evals-code-runOpusmediumJudge quality determines whether the lessons loop improves or degrades skills; the rubric is fixed, so medium suffices.
evals-e2e-runOpusmediumSame reasoning as code evals; consistency judging across long artefacts favours Opus over Sonnet.
lessons-capture (internal)SonnetlowDistilling a useful lesson takes some judgement, but weak entries get filtered later by lessons-learn.
lessons-learnFablehighRare, user-triggered, and edits SKILL.md — the product itself. Changes propagate to every future run: highest leverage per token in the repo.
pushHaikulowMechanical commit + push.
releaseSonnetmediumProcedural, but changelog prose and version judgement deserve a mid tier.
Pattern: Fable where a mistake is expensive and reviewed rarely (design, skill-editing) · Opus where sustained reasoning or judging quality compounds (storm, bug-fix, implement, evals) · Sonnet for competent mid-weight work · Haiku for anything deterministic or read-only. Internal helpers load inline via Skill and always inherit the caller's model — their rows show the minimum tier that would suffice, so they never justify a bigger session model on their own.
